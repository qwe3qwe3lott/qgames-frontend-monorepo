# Игры: правила кода пакетов игр и партии на фронте

Вложенный CLAUDE.md: дополняет корневой `CLAUDE.md` (§2) для пакетов `packages/games/*`, а также `@qgames/game-core`, `@qgames/game-ui`, доски и применения патчей партии (корневой файл ссылается сюда). Устройство партии на фронте — `adr/c4/3-frontend.md`, формат событий — `adr/c4/3-backend-games.md`, обоснования — `adr/frontend/frontend-game-logic.md` (`adr/` — `../qgames-workspace/adr` от корня репозитория).

- Игра — пакет `packages/games/<код>` с именем `@qgames/game-<код>`. Зависит только от `@qgames/ui`, `@qgames/game-ui`, `@qgames/game-core`, `@qgames/api` (только сгенерированные схемы и типы, без запросов) и библиотек каталога. Игры друг от друга не зависят.
- Портал подключает пакет игры только динамическим `import()` в `entities/game/model/registry.ts`. Статический импорт `@qgames/game-*` (кроме `@qgames/game-ui`, `@qgames/game-core` и `import type`) запрещён ESLint.
- **Правил игры и кодов событий в коде фронта нет.** Состояние меняется только общим `applySessionEvent` по `method`, `code` используется только для логов. Своих редьюсеров у игр нет. Действия берутся только из `players[].moveOptions` зрителя. Исключение — подсказки ввода пути по флагам `meta.moveRules` (`lib/path.ts` пакета игры), вариантов правил фронт не знает.
- **Проверка состояния:** на снапшоте и после каждого патча — общая схема `status`/`meta` (без `meta.moveRules`), совпадение `meta.game.code` с игрой комнаты, затем `checkSessionState`: guard core `isCoreState` и guard **только игровых полей** `isGameState` (поля игры в объектах игроков и форма `meta.moveRules` — тоже в нём). Guard'ы строятся на сгенерированных Zod-схемах (`safeParse`, без `as`). Любой провал — переподключение. Неразборчивое состояние в доске — сообщение, а не падение.
- Форма модуля игры — `GameModule = {Board, PlayerCard?, isGameState}`, описана в портале (`entities/game/model/types.ts`). Пакет описывает те же пропсы у себя (`BoardProps`, `GamePlayerCardProps`), совместимость проверяет TypeScript в реестре.
- **Список игроков на странице один** (`RoomPanel`), своего списка игроков у доски нет. Данные игры об игроке (цвет, ходящий, часы, пометки вроде «Предлагает ничью») игра показывает своей карточкой `PlayerCard`: она получает `{session, viewerId, card}` и рисует базовую `PlayerCard` из `@qgames/game-ui` с `card`, дописывая `badges`, `active`, `note`, `status`; не участнику партии или при неразборчивом состоянии — базовую как есть. Портал подставляет её через `SessionPlayerCard` (`widgets/gameBoard`), `PlayerList` принимает реализацию карточки пропом `Card` и от игр не зависит.
- Ход отправляется конвертом `{type, data?}` законченным целиком. Локальной симуляции нет. После 422 `MOVE_REJECTED` выбор сбрасывается.
- Итог партии читается из `state.result` и показывается через `GameOver` (`@qgames/game-ui`). Текст причины по `reason` лежит в пакете игры.
- **Время:** показывать ли часы, решает только `activeTimer`. Часы игрока — `playerClock(...)` → `ChessClock` в `status` карточки игрока, добавка — `ClockIncrement` на доске (только если больше нуля). Отсчёт идёт с `clockOffsetMs` по `serverTime` снапшота.
- `@qgames/game-ui` — только презентационные компоненты: данные через props, без запросов и сторов.
- Игре без пакета на фронте соответствует запись в реестре без `load`, пакет не заводится.
